Manual Python Implementation

Each Quarto Manual page is one operational step in the manual. A page should tell the user:

  • what must already be true;
  • what they need to do now;
  • how they can prove the step worked.

To make that structure explicit, every page must use three semantic block types:

  • exactly one .manual-prereq block;
  • one or more .manual-procedure blocks;
  • exactly one .manual-check block.

These blocks give the page a predictable structure for both the reader and the manual tooling. They also let the manual derive a checklist view across all pages without turning the manual into a hidden workflow engine.

5.1 Required Page Structure

Start each page with normal Quarto metadata:

---
title: "Assemble Python Environment"
manual:
  page: 2
---

Then write the page using the required manual blocks.

5.1.1 1. Prerequisite Block

The prerequisite block explains what the user must already have before this step is actionable. This is the place to inspect the current project state, load shared helper code, or confirm that earlier manual steps are complete.

There must be exactly one prerequisite block on the page. In this manual, the prerequisite block should include the shared checklist definition so that each page starts from the same declared manual state.1

5.3 Implementation

Python is great for object oriented workflows. One useful Python implementation for a manual is as a Checklist object. By using a dataclass, we can create a flexible checklist object that summarize a manual and its pages. In that design, the checklist is not the manual itself. It is a structured representation of the manual’s ordered steps. Each page has a number, title, and semantic content for prerequisite, procedure, and check blocks.

5.4 Page

First, we’ll define a page in the checklist.

from __future__ import annotations

from dataclasses import dataclass, field
from pathlib import Path
from typing import Callable, Iterable, Sequence

import warnings


CheckFn = Callable[["Checklist", "Page"], None]


@dataclass(frozen=True)
class Page:
    """One checklist step in a Quarto Manual."""

    title: str
    number: int
    prerequisite: str
    procedures: tuple[str, ...]
    check: str

    def __post_init__(self) -> None:
        if not self.title.strip():
            raise ValueError("Page.title must not be empty.")

        if self.number < 1:
            raise ValueError("Page.number must be >= 1.")

        if not self.prerequisite.strip():
            raise ValueError("Page.prerequisite must not be empty.")

        if not self.check.strip():
            raise ValueError("Page.check must not be empty.")

        if len(self.procedures) < 1:
            raise ValueError("Page.procedures must contain at least one procedure block.")

        if any(not step.strip() for step in self.procedures):
            raise ValueError("Page.procedures may not contain empty procedure blocks.")

    @property
    def procedure_count(self) -> int:
        return len(self.procedures)

    def summary(self) -> dict:
        return {
            "title": self.title,
            "number": self.number,
            "prerequisite": self.prerequisite,
            "procedure_count": self.procedure_count,
            "check": self.check,
        }

The Checklist class is a container for the pages in the manual. It can be used to summarize the manual, report missing sections, and help the user see how much of the procedure has been covered.

It has a simple initialization API requiring the title of the project, the root directory of the project, and a sequence of Page objects. The Checklist class validates that the pages are numbered in order and that there are no duplicate page numbers.

from pathlib import Path

@dataclass(frozen=True)
class Checklist:
    """Declarative description of a Quarto Manual."""

    project_title: str
    project_root: Path
    pages: tuple[Page, ...] = field(default_factory=tuple)

    def __post_init__(self) -> None:
        if not self.project_title.strip():
            raise ValueError("Checklist.project_title must not be empty.")

        if not Path(self.project_root).is_dir():
            raise ValueError("Checklist.project_root must be an existing directory.")

        if len(self.pages) < 1:
            warnings.warn(
                "Checklist.pages is empty; this is useful during testing, but an end-user manual should contain at least one page.",
                stacklevel=2,
            )

        numbers = [page.number for page in self.pages]
        if len(numbers) != len(set(numbers)):
            raise ValueError("Checklist page numbers must be unique.")

        if numbers != sorted(numbers):
            raise ValueError("Checklist pages must be ordered by page number.")

    @property
    def page_count(self) -> int:
        return len(self.pages)

    @property
    def check_count(self) -> int:
        return len(self.pages)

    @property
    def procedure_count(self) -> int:
        return sum(page.procedure_count for page in self.pages)

    def get_page(self, number: int) -> Page:
        for page in self.pages:
            if page.number == number:
                return page
        raise KeyError(f"No page found for number {number}.")

    def summary(self) -> dict:
        return {
            "project_title": self.project_title,
            "project_root": str(self.project_root),
            "page_count": self.page_count,
            "procedure_count": self.procedure_count,
            "check_count": self.check_count,
            "pages": [page.summary() for page in self.pages],
        }

    def __repr__(self) -> str:
        return (
            f"Checklist("
            f"project_title={self.project_title!r}, "
            f"pages={self.page_count}, "
            f"project_root={str(self.project_root)!r})"
        )

This allows us to create a very simple checklist for a manual:

5.4.1 2. Procedure Blocks

Procedure blocks contain the actual work of the page. A page may need one procedure block or several, depending on how much scaffolding you want to give the user.

There must be at least one procedure block on the page.

You can use multiple procedure blocks when the step has distinct parts, such as
writing a file and then installing dependencies.

### 3. Check Block

The check block proves whether the page succeeded. This should inspect the real
project state and fail clearly when the step is incomplete or incorrect.

There must be exactly one check block on the page.

5.5 Authoring Rules

When writing a page, keep these rules in mind:

  • use exactly one .manual-prereq block;
  • use at least one .manual-procedure block;
  • use exactly one .manual-check block;
  • let checks inspect real files, paths, configs, logs, or rendered outputs when possible;
  • keep the page focused on one operational step.

The goal of a page is not just to explain a step. The goal is to help the user perform that step and prove that it is complete.

  1. Notebook authoring can make cross-page state hard to reason about. By keeping the checklist definition in one included file, each page can recreate the same shared base objects in its own execution context. This gives authors one source of truth while avoiding hidden dependence on state from another page.↩︎
